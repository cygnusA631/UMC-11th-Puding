# 6주차 직접 캡처

사용자가 촬영한 원본 18장(BE 10장, PE 8장)을 보관한다. 원본 이미지는 수정하지 않았다. 아래는 이미지에서 실제로 확인되는 내용이며, 자동 검증 결과와는 구분한다.

## Backend

- `01_회원가입_201.png`: 회원가입 201 응답.
- `03_중복요청.png`, `04_중복요청.png`: 이메일·닉네임 중복 요청 화면.
- `05_입력검증실패.png`: 입력 검증 실패 화면.
- `06_평점등록_201.png`: 평점 등록 201 응답.
- `11_평점수정_200.png`: 평점 수정 200 응답.
- `14_삭제.png`: 삭제 화면.
- `17_DB_UNIQUE_테스트통과.png`: DB UNIQUE 제약 경로 테스트 결과.
- **`07_중복요청.png`는 재촬영 필요**: 요청 의도는 평점 중복 409이지만, 실제 응답은 201이고 Postman 테스트는 0/2다. 이 이미지를 중복 409 성공 증거로 사용하지 않는다. `06`에서 만든 평점의 회원·영화 조합을 유지한 채 `07`을 호출해 409를 다시 확인한다.
- **`09_타인평점수정_404.png`는 재촬영 필요**: 실제 응답은 404/RATING4041이고 Postman 테스트는 1/2다. 존재하는 평점을 다른 회원이 수정할 때의 403 증거는 아니다. 삭제 전 유효한 ratingId와 다른 회원의 memberId를 사용해 `09`를 다시 확인한다.

## Frontend

- `목록1p.png`, `목록2p.png`: 영화 목록과 page별 Query Devtools.
- `영화검색결과.png`: 검색 결과와 검색 Query.
- `영화상세.png`: 상세 화면과 상세 Query. **Fresh 1 상태**로, 30초 뒤 stale 상태를 촬영한 이미지는 아니다.
- `오류_재시도.png`, `빈검색결과.png`, `로딩_현재화면.png`: 합성 응답을 사용하는 로컬 재현 화면.
- `Network_캐시재사용기록.png`: Network 요청 기록과 Query 캐시.

30초 stale 상태 사진은 별도로 추가할 수 있다. 자동 시간 검증은 설정값을 유지한 가상 시계를 사용했으며, 그 결과는 상위 폴더의 `query-verification.json`, `query-browser-verification.json`에 기록되어 있다.

## 검증 원본

백엔드 통합 테스트 16개와 HTTP 검증 27건, 프론트 Query 11개·브라우저 12개·실제 TMDB 4개의 검증 결과는 상위 폴더의 JSON 파일을 참고한다. 두 Postman 캡처의 불일치는 이 검증 결과를 대체하거나 변경하지 않는다.
