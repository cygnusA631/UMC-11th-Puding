# 미션별 SQL 설명

[2주차 워크북](https://app.notion.com/p/2-SQL-31d5056fdfa98396ba25014d71388a20?source=copy_link)의 공통 도서 예제와 1주차 리워드 ERD를 사용합니다. 아래 설명은 SQL을 읽고 제출 기록을 작성할 때 참고할 초안입니다. 학습자의 실행 경험이나 회고를 대신 주장하지 않습니다.

## 미션 1 — 문학 분류의 대여 가능한 도서

`book`과 `category`를 분류 FK로 `INNER JOIN`하고, 분류가 문학이면서 대여 가능한 도서만 `WHERE`로 선택합니다. 제목·설명·분류를 출력하며, 워크북에서 정한 최신 기준인 `book_id DESC`로 정렬한 뒤 `LIMIT 10`을 적용합니다. ID 내림차순을 최신 순서로 쓰는 것은 이 실습의 기준이며, 등록 시각이 있는 실제 서비스라면 등록 시각을 기준으로 정렬하는 방식을 검토할 수 있습니다.

예상 결과는 `달빛 도서관 / 소설 / 문학` 1행입니다. 대여 가능 여부는 공통 스키마의 도서 상태를 사용하며, 미반납 대여 내역과의 데이터 일관성을 자동으로 갱신하는 기능까지 구현한 것은 아닙니다.

## 미션 2 — 특정 사용자의 미반납 도서

`rental`과 `book`을 도서 FK로 `INNER JOIN`하고, 지정한 사용자와 `returned_at IS NULL` 조건에 맞는 대여 내역을 남깁니다. 도서 제목·대여 시각·반납 예정 시각을 반환하며, `due_at ASC`로 정렬하고 같은 반납 예정 시각일 때는 `rental_id`로 순서를 고정합니다. 사용자 정보를 출력하지 않으므로 `users`를 추가로 JOIN하지 않아도 대여 내역의 사용자 FK로 필터링할 수 있습니다.

민서(`user_id = 1`)의 결과는 `겨울의 편지` 1행입니다. 반납 예정 시각이 지난 미반납 도서는 연체 상태여도 포함되며, 반납 완료 여부와 연체 여부는 구분해야 합니다.

## 미션 3 — 도서의 태그와 사용자별 좋아요

기준인 `book`에서 `book_tag`를 거쳐 `tag`를 `LEFT JOIN`하고, 조회 중인 사용자의 `book_like`도 `LEFT JOIN`합니다. 태그가 여러 개라면 태그별로 여러 행을 반환하며, 좋아요는 연결된 행의 존재 여부를 `1` 또는 `0`으로 나타냅니다. `book_like`의 사용자 조건을 `ON`에 두어 해당 사용자가 좋아요를 누르지 않은 도서도 결과에 남도록 합니다.

특정 도서를 고르는 `book_id` 조건은 기준 테이블의 조건이므로 `WHERE`에 둡니다. 반면 오른쪽 `book_like`의 `user_id` 조건을 `WHERE`로 옮기면 연결이 없어 NULL인 행이 걸러져, 좋아요를 누르지 않은 도서가 결과에서 사라집니다.

기본 확인 사례는 다음과 같습니다.

- 민서(`user_id = 1`), `달빛 도서관`(`book_id = 1`): `소설`, `추천` 2행이며 좋아요는 모두 `1`입니다.
- 수현(`user_id = 2`), 같은 도서: 태그 2행을 유지하며 좋아요는 모두 `0`이어야 합니다.
- 민서(`user_id = 1`), `겨울의 편지`(`book_id = 2`): 태그가 없어도 도서 1행을 유지하며 태그는 NULL, 좋아요는 `0`이어야 합니다.
- 존재하지 않는 도서 ID: 기준 `book`에 행이 없으므로 결과도 0행입니다. `LEFT JOIN`은 존재하지 않는 도서를 새로 만들지 않습니다.

태그와 좋아요의 중복 연결을 막는 키가 있으면 한 사용자의 좋아요 때문에 태그 행이 불필요하게 늘어나는 것을 막을 수 있습니다. 이번 미션의 태그 목록은 태그별 행이며, 태그 문자열 하나로 합치는 집계는 필수 요구사항에 포함하지 않았습니다.

## 확장 — 지역별로 새로 도전 가능한 리워드 미션

1주차 ERD의 `mission → store → region` 경로로 지역을 선택하고, 가게의 `food_category`를 연결해 표시할 정보를 얻습니다. 지정한 회원의 `member_mission`을 `LEFT JOIN`한 뒤 연결된 이력이 없는 미션만 남기고, 마감 전이며 미션·가게·지역·음식 카테고리가 논리 삭제되지 않았다는 조건을 적용합니다. 마감 시각이 가까운 순서로 정렬하고 같은 시각의 미션은 ID로 순서를 고정한 뒤, `LIMIT 10 OFFSET 0`으로 첫 페이지를 반환합니다.

이 확장에서 **새로 도전 가능**은 다음 가정을 따릅니다.

- 지정한 지역의 미션입니다. 예제 지역 `1`은 안암동입니다.
- `deadline > 기준 시각`입니다. 기준 시각과 마감 시각이 같으면 이미 마감된 것으로 봅니다.
- 해당 미션과 가게·지역·음식 카테고리의 `deleted_at`이 모두 NULL입니다.
- 지정한 회원이 이 미션에 도전한 기록이 한 번도 없습니다. 진행·완료·취소 상태를 모두 포함하며, 논리 삭제된 수행 기록도 과거 도전으로 취급합니다.
- 다른 회원의 수행 이력은 조회 회원의 도전 가능 여부에 영향을 주지 않습니다. 따라서 회원 필터는 `member_mission` JOIN의 `ON`에 둡니다.

1주차의 `(member_id, mission_id)` UNIQUE는 취소 또는 논리 삭제 후에도 유지됩니다. 따라서 이 예제는 같은 미션에 새 기록을 넣어 재도전하는 것을 허용하지 않으며, 재도전을 허용하려면 기존 수행 행 복원·상태 변경 등의 별도 정책을 정해야 합니다.

회원 `1`, 지역 `1`, 기준 시각 `2026-09-22 12:00:00`에서 기대 순서는 미션 ID `8`(9월 23일 마감), `2`(9월 24일 마감)입니다. 날짜가 지나도 초기 결과를 재현할 수 있도록 예제에서는 기준 시각을 고정했으며, 실제 현재 기준 조회에서는 그 값을 현재 시각으로 바꿉니다.
