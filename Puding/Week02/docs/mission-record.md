# 2주차 미션 기록

## 요구사항을 나눈 과정

워크북의 도서 대여 공통 모델과 지난주에 만든 리워드 모델이 달라, 공통 문제는 `umc_week02_library`, 개인 ERD 확장은 `umc_week02_reward`로 구분했다. 워크북에 제공된 공통 스키마의 컬럼·키와 더미 데이터는 그대로 사용했고, 리워드 확장에는 지난주 9개 테이블을 복사했다.

1. 미션 1은 화면에 도서의 제목·설명과 분류 이름이 필요하므로 `book`에서 시작해 `category`를 연결했다. 문학과 대여 가능 상태를 모두 만족해야 한다.
2. 미션 2는 특정 회원의 대여 내역이 기준이므로 `rental`에서 시작했다. `book`은 제목을 가져오기 위해 연결하며, 반납 예정일이 지난 경우도 `returned_at IS NULL`이면 미반납 목록에 남는다.
3. 미션 3은 도서 한 권을 기준으로 태그와 좋아요를 연결했다. 태그나 좋아요가 없는 도서도 보여야 하므로 `LEFT JOIN`을 사용하고, 현재 사용자 조건은 좋아요 JOIN의 `ON`에 두었다.
4. 확장은 “안암동에서 처음 도전할 수 있는 미션을 마감순으로 보여 준다”로 정했다. 미션·가게·지역·음식 분류를 연결하고, 현재 회원의 수행 이력이 없는 항목을 조회했다.

각 SQL의 설명은 [미션별 설명](mission-explanations.md), 테이블 관계는 [공통 ERD](library-erd.mmd), 실제 조회의 연결 경로는 [JOIN 경로](join-paths.mmd)에 기록했다. 개인 리워드 ERD는 [1주차 ERDCloud](https://www.erdcloud.com/d/sgiC7TXnmYk7C7ha3)를 사용했다.

## 구현하면서 확인한 사항

- 워크북 본문에는 알림 더미 데이터가 언급되지만, 실제 제공 INSERT에는 알림 행이 없다. 원본을 유지하여 `notification`은 0행으로 두었다.
- 공통 예제의 대여 가능 도서는 2권뿐이다. `LIMIT 10 OFFSET 10`의 결과가 비어 있는 것은 정상이다.
- 리워드의 `(member_id, mission_id)` UNIQUE는 완료·취소·논리 삭제 이후에도 남는다. 확장의 “새로운 도전”은 기존 이력이 한 번도 없는 경우로 정했다.
- 확장 데이터의 조회 시각은 `2026-09-22 12:00:00`으로 고정했다. 실습 날짜가 달라져도 동일한 결과를 재현할 수 있다.
- 없는 태그, 없는 좋아요, 다른 사용자의 좋아요, 존재하지 않는 도서, 다른 지역, 삭제된 지역을 별도로 확인하도록 `verify.py`에 검증 사례를 작성했다.

## 환경 관련 문제와 해결

**문제:** 로컬의 `mysql` 명령은 MariaDB 클라이언트였으며, `/tmp/mysql.sock`에 연결되는 DB 서버가 실행 중이지 않았다.

**해결:** Colima를 시작하고 과제 전용 MySQL 8.4 컨테이너를 준비했다. 기존 로컬 DB와 충돌하지 않도록 `127.0.0.1:13306`에 연결하고, `mysql.sh`로 컨테이너 안의 MySQL 클라이언트를 사용하도록 했다. Workbench에서도 동일한 서버로 연결할 수 있다.
